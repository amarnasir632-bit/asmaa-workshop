# مراجعة وثيقة المتطلبات

**المرجع:** `SRS.md`، الإصدار 1.0، مسودة للمراجعة والاعتماد النهائي، 14 أكتوبر 2026. **الحالة:** فحص مكتبي للدفعة الأولى، دون تطبيق أو اتصال بقاعدة بيانات.

## خلاصة الفحص

قُرئت الوثيقة كاملة (1228 سطراً). جذر المشروع لا يحتوي إلا على `SRS.md`، ولا يظهر كود أو ملفات إعداد أو شعار/هوية بصرية. ملف SRS غير متعقب في Git ولم يُعدّل.

النطاق تطبيق ويب عربي RTL لمشغل ومخزن واحد، بعملة SDG، لإدارة العملاء والأطفال والمقاسات والمدارس والأصناف والطلبات والإنتاج والمخزون والتسليم والمالية والتقارير والاستعلام المحدود والتدقيق والترحيل والنسخ الاحتياطي. لا يشمل الإصدار الأول حسابات العميل/الطفل/الترزي، بوابة دفع، فروعاً متعددة أو محاسبة مزدوجة.

## الوحدات المطلوبة

1. المصادقة والمستخدمون والأدوار والصلاحيات.
2. أولياء الأمور والأطفال والمقاسات الحالية والتاريخية.
3. المدارس والمراحل والأصناف وخصائصها والأسعار التاريخية.
4. الطلبات الفردية بأنواعها الثلاثة والعقود/الطلبات المدرسية الجماعية.
5. الإنتاج والإرسال إلى الترزي والاستلام الجزئي والكلي وتتبع العهدة.
6. التسليم الفردي والجماعي والجزئي.
7. المخزون الجاهز والأرصدة الافتتاحية والحركات والتصحيحات.
8. المبيعات والدفعات والتحويلات وأدلتها الخاصة.
9. المصروفات والملخص المالي والربح التقديري.
10. الإلغاء والخصومات والاستردادات كسجلات مستقلة.
11. لوحة التحكم والإشعارات الداخلية.
12. التقارير والتصفية والطباعة وPDF.
13. استعلام عام محدود ومقاوم للتخمين.
14. سجل التدقيق المحمي.
15. ترحيل التاريخ الورقي ومشكلات البيانات غير المؤكدة.
16. النسخ الاحتياطي والاستعادة واختباراتهما.

## قواعد العمل الحرجة

- تثبيت السعر ولقطة المقاسات داخل الطلب تاريخياً.
- فصل الحالة التشغيلية ومرحلة الإنتاج والحالة المالية والتنبيه المحسوب للتأخير.
- فصل قيمة المبيعات عن التحصيل المؤكد وغير المؤكد والرصيد المستحق؛ دعم الدفعات المتعددة والجزئية.
- لا يعد التحويل مؤكداً عند تسجيله؛ المدير وحده يؤكده. الأدلة اختيارية وخاصة ولا تنشئ دفعة ثانية.
- المدير وحده يعتمد الإلغاء والاسترداد والتصحيحات المالية الحساسة والجرد والتصحيحات التاريخية الحساسة.
- قرار خصم الإلغاء الأولي يحدده المدير عند الإلغاء وفق المرحلة؛ لا نسبة ثابتة. تسجل الأسباب والمرحلة والهوية والتوقيت.
- لا تسليم مع رصيد مستحق، ولا تسليم جزئي لعقد مدرسي قبل كامل السداد؛ بعده تتبع الكميات في كل تسليم.
- منع المخزون السالب والبيع فوق المتاح؛ عهدة الترزي ليست مخزوناً جاهزاً. تسجل كل حركة/استلام/تسليم بكمية مستقلة.
- لا حذف يمحو أثراً تشغيلياً/مالياً؛ التعديل الحساس يترك أثراً قابلاً للتدقيق.
- لا تعرض الواجهة العامة إلا «جاهز/غير جاهز» و«مسدد/غير مسدد»؛ لا قوائم أطفال ولا مقاسات أو مبالغ أو اتصال أو مستندات.
- لا تخمين لبيانات الترحيل. الربح التقديري ليس صافي ربح محاسبياً.
- لا تعتبر النسخ أو RPO/RTO متحققة دون آلية واختبار استعادة ناجح.

## المحسوم والمفتوح

قواعد التشغيل والمالية والإلغاء والتسليم والخصوصية محددة بما يكفي للتصميم، ولم يظهر تعارض جوهري بينها. لكن SRS موسوم «مسودة موحدة للمراجعة والاعتماد النهائي» ويشترط عدم بدء البرمجة/قاعدة البيانات قبل الاعتماد. لذا لا يبدأ التطبيق أو قاعدة البيانات قبل الاعتماد الرسمي.

ما زال مفتوحاً في SRS: مزود الاستضافة وإتاحته من السودان، محرك قاعدة البيانات، مصفوفة صلاحيات الموظف التفصيلية، حساب السداد مع تحويل معلق واسترداد، تمثيل العقد/الطلب الجماعي، حد الملفات، معدل الاستعلام، اختبار الأداء، سياسة الاحتفاظ القانونية، وتفعيل النسخ الخارجية (DEC-001..012). لا يجوز حسم سياسة تشغيلية فيها بالافتراض.

## المخاطر التقنية الأولية

- الاستضافة المجانية قد لا توفر جذر ويب `public`، أو CLI/Composer/Cron، أو رفعاً آمناً ونسخاً خارجياً. دعم PHP وحده لا يثبت دعم Laravel.
- لم يختبر حساب فعلي: نسخة PHP وامتداداتها وقيود الطلبات والملفات أو الوصول من السودان.
- لا توجد ملفات هوية؛ الواجهة المؤقتة تحتاج CSS variables دون اختراع شعار أو ألوان نهائية.
- بيانات الأطفال والمالية ومستندات التحويل تجعل حماية الملفات والجلسات والنسخ شرطاً قبل بيانات حقيقية.
- الاسم في الاستعلام العام لا يثبت الهوية؛ يلزم تقليل الإفصاح وتحديد المعدل.
- السجلات الورقية قد تكون ناقصة/متعارضة؛ يلزم تمييزها ومراجعتها دون تخمين.
- 50 مستخدماً و95% خلال ثانيتين هدف يتطلب قياساً؛ قد تمنع الخطة المجانية تحقيقه.
