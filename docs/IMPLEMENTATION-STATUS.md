# حالة التنفيذ

آخر تحديث: 14 أكتوبر 2026.

## الموافقات والحدود

- SRS v1.0 معتمدة حسب تحديث المالك.
- بدأ تنفيذ التطبيق محلياً؛ لا نشر عام أو تشغيل على قاعدة بيانات حقيقية، ولا توجد بيانات حقيقية.
- لا تعتمد استضافة مجانية نهائية قبل تجربة موثقة؛ توافق النشر لا يزال مفتوحاً.
- اختير Cloudflare Workers + D1 كهدف نقل، مع إبقاء Laravel مرجعاً حتى اكتمال تكافؤ الوظائف. `cloudflare/` يطابق مخطط SQLite الحالي، ويحتوي على مصادقة وواجهات API أولية للأسر والمستخدمين والكتالوج والطلبات والمالية والمخزون والإنتاج والتقارير والتدقيق والترحيل التاريخي. الواجهة لا تزال جزئية، كما أن أدلة الدفع الخاصة وR2 والنسخ والاستعادة واستيراد البيانات والمصالحة وPDF والاستعلام العام ليست مكتملة. لم ينشر المشروع أو ينشأ D1 إنتاجي؛ النسخة غير جاهزة لبيانات حقيقية أو تشغيل إنتاجي. راجع `docs/CLOUDFLARE-MIGRATION.md`.

## المنجز

- الدفعة 1: فحص SRS والمشروع، تقييم الخيارات، المراجعة وخطة التنفيذ والقرارات ومصفوفة التتبع.
- الدفعة 2: مخطط البيانات المنطقي، مصفوفة الصلاحيات، قواعد التخزين الخاص والتدقيق والنسخ.
- الدفعة 3: Laravel 13/Blade/Tailwind، إعدادات وأسرار نموذجية، migrations (لا قاعدة تشغيلية)، مصادقة وجلسات وأدوار/صلاحيات، إنشاء أول مدير من CLI، إدارة المستخدمين من المدير، سجل تدقيق، لوحة مبدئية.
- الدفعة 4 جزئياً: ملفات أولياء الأمور والأطفال والمقاسات الحالية، المدارس والمراحل وأنواع الملابس وتركيبات الأصناف، إنشاء/عرض الطلبات الفردية متعددة البنود وعقود المدارس مع مستفيدين وبنود مفصلة، وثبات الأسعار ولقطات المقاسات.
- الدفعة 3 جزئياً: إدارة المستخدمين للمدير، قفل حساب آخر مدير، وتسجيل أحداث التدقيق.
- الدفعة 6 جزئياً: تسجيل المصروفات بفئات SRS، صلاحيات على السجل (الموظف يرى سجلاته فقط)، ومنع التعديل/الحذف المباشر. سجل التدقيق لديه واجهة قراءة فقط للمدير.
- الدفعة 6 جزئياً: شاشة تسجيل الدفعات النقدية والتحويلات، رصيد محسوب من خدمة مالية مركزية، اعتماد التحويل للمدير فقط، مرفقات خاصة اختيارية مع تحقق النوع والحجم وبصمة SHA-256، ومنع تكرار رقم العملية في الطلب. ترتبط الخدمة الآن بالتسليم والإلغاء والاسترداد والتقارير، واختبارات الوحدات المالية ناجحة.
- الدفعة 5 جزئياً: تسجيل تسليم جزئي/كامل على مستوى الطلب مع اسم المستلم والإيصال، احتساب الكميات المتبقية، منع التسليم قبل سداد كامل الطلب أو الطلب الملغي، وتسجيل حركة خصم مخزون عند تسليم الملابس الجاهزة. يغلق الطلب تشغيلياً بعد اكتمال جميع الكميات. اختبارات الوحدة الجديدة ناجحة (2 اختبار/17 assertion ضمن اختبار الدفعتين والتسليم).
- الدفعة 5 جزئياً: بيع الملابس الجاهزة أصبح يطلب الصنف المخزني ويظهر المتاح، يقفل رصيد الصنف في المعاملة ويتحقق من الكمية قبل إنشاء الطلب، ثم يخصم المخزون ويسجل حركة البيع. يعيد الإلغاء الكميات التي لم تسلم إلى المخزون بحركة إلغاء منفصلة. التسليم لا يخصم البيع مرتين. اختبارات الإنشاء/المخزون/الإلغاء ناجحة.
- الدفعة 6 جزئياً: اعتماد الإلغاء وخصم يختاره المدير حسب المرحلة، وحساب المبلغ المستحق إرجاعه من التحصيل الصافي. اعتماد الاسترداد وتنفيذ دفعاته الفعلية كسجلات منفصلة، ربط الدفعة الأصلية، وفحص كمية وحالة الملابس المرتجعة قبل الموافقة. المرتجع الجاهز الصالح يعاد للمخزون بحركة مستقلة. تصحيح الخصم أو مبلغ الاسترداد المعتمد للمدير فقط مع تسجيل السابق والجديد والسبب في جدول مستقل وسجل التدقيق.
- الدفعة 7 جزئياً: صفحة استعلام عامة بالاسم/رقم التواصل، تسأل عن التواصل عند تكرار الاسم، تحد محاولات البحث إلى 5 في الدقيقة و30 يومياً لكل IP، وتعرض الجاهزية والسداد فقط مع تنبيه محدودية التحقق بالاسم. اختبارات التكرار/الحد/عدم كشف الأسماء والمبالغ ناجحة.
- الدفعة 6 جزئياً: تقارير مالية وتشغيلية بفلاتر الفترة والمدرسة وولي الأمر والحالة؛ اختبر عزل بيانات ولي الأمر وحالة الطلب، ويلزم اختبار صريح لفلتر المدرسة. المبيعات حسب المدرسة وتاريخ الطلب، والتحصيل النقدي حسب تاريخ قبضه والتحويل حسب اعتماد المدير، والاستردادات الفعلية والمصروفات والديون منفصلة. يظهر الربح التقديري وفق القرار المعتمد مع تنبيه حدوده. تشمل الصفحة حالة الطلبات وعمل الترزي ومخزون الأصناف والحركات. أضيف تنزيل PDF مباشر باستخدام `tc-lib-pdf` وDejaVu. الواجهة تستخدم Tajawal المحلي حسب توجيه المالك؛ اختبار Tajawal داخل PDF أظهر محارف مفقودة بصرياً، لذلك PDF لا يطابق الهوية بعد ويلزم إصلاحه واختبار التقرير كاملاً.
- الدفعة 5 جزئياً: إنشاء مهام الإنتاج، تحديث المرحلة مع السبب، إرسال كميات مستقلة للترزي واستلامها جزئياً؛ يحسب النظام المتبقي ويشتق تنبيه التأخير من الموعد. إدارة الرصيد الافتتاحي كمسودة حتى اعتماد المدير، وتسويات الجرد تتطلب اعتماداً وتنتج حركات دفترية؛ يمنع الرصيد السالب داخل المعاملة. واجهات RTL، صلاحيات خادمية، قفل للصفوف وسجل تدقيق.
- النسخ: أوامر إنشاء/احتفاظ/استعادة مشفرة، جدول Laravel Scheduler، وقرص نسخ محلي افتراضي. اختبار إنشاء/استعادة معزول ناجح. التخزين الخارجي والـcron الحقيقي لم يضبطا، لذلك RPO/RTO غير متحققة.
- الدفعة 7 جزئياً: لوحة التحكم تعرض مؤشرات وفق الصلاحيات، وإشعارات داخلية متجددة عند فتح اللوحة للتأخير والجاهزية والأرصدة؛ يمكن وسمها مقروءة وتُحل تلقائياً عند زوال السبب. اختبارات التكرار، الحل، قراءة الإشعار ورفض مستخدم آخر ناجحة. لا يرسل النظام تنبيهات خارجية.
- أصول الهوية `logo.png` و`icon.png` وخط Tajawal المحلي تستخدمها الواجهة. لم يقدم ترخيص Tajawal، لذلك لم يحسم حق إعادة توزيع الخط.

## الاختبارات الفعلية

آخر تشغيل كامل: 52 اختباراً ناجحاً و364 assertion على SQLite in-memory. نجحت `vendor/bin/pint --test` و`npm run build` و`composer validate`. أضيفت حزمة S3 الرسمية لـFlysystem واختبرنا إنشاء قرص S3-compatible بإعداد اصطناعي دون الاتصال بمزود، مع اختبار كتابة نسخة مشفرة على قرص fake. أضيف GitHub Actions لتشغيل SQLite والبناء وPint وComposer وMySQL 8.4 بعد الرفع. تعذر تشغيل MySQL محلياً: Podman لا يستطيع تهيئة runtime أو تنزيل الصور العامة في بيئة التنفيذ. لا تزال اختبارات CI الفعلية واختبارات الاستضافة والأداء والاستعادة الخارجية غير موجودة.

## المتبقي

أضيفت واجهة للدفعات والسجلات التاريخية مع مصدر/تاريخ/درجة وضوح، كشف تطابق حرفي، مراجعة المدير، سجل نسخ للتصحيح وسجل تدقيق. اختبارات الصلاحيات والتكرار والتصحيح والعزل عن الدفعات وحركات المخزون ناجحة. هذا أرشيف مرحلي فقط؛ لا رفع ملفات أو اعتماد نهائي للدفعة أو تحويل إلى الكيانات التشغيلية ومصالحة مالية/مخزنية بعد.

المتبقي: استكمال الترحيل التاريخي الفعلي، تغطية فلاتر التقارير آلياً ومراجعة جودة PDF الكامل، وإكمال تغطية المتطلبات والاختبارات. تعديل الطلبات وإدارة بعض حالات التشغيل غير مكتملة. يلزم اختبار MySQL، فحص العرض عبر المتصفح، واختبار التثبيت والنشر على مضيف مرشح. جرت محاولة فحص بصري لواجهة الموقع، لكن البيئة رفضت فتح منفذ خادم التطوير؛ لا يوجد تحقق بصري شامل بعد. النسخ/الاستعادة أداة محلية؛ إعداد الوجهة الخارجية والجدولة الحقيقية وRPO/RTO غير مكتملة. لم يُقَس أداء 50 مستخدماً/95% خلال ثانيتين. هذه النسخة ليست جاهزة لإدخال بيانات تشغيل حقيقية أو للنشر.
