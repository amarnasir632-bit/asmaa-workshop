# النشر التجريبي على InfinityFree — دليل كامل

هذا الدليل يشرح نشر تطبيق «مشغل أسماء» (Laravel 13) على خطة InfinityFree المجانية
باستخدام PHP + MySQL، **ببيانات اصطناعية فقط**.

> تحذير: هذه نسخة تجريبية. لا تُدخل بيانات عملاء أو مالية حقيقية قبل إكمال النسخ
> الاحتياطي والاستعادة ومراجعة الأمان والتحقق من العزل على الخادم.

الحزمة الجاهزة (مبنية فعلاً): `build/infinityfree-htdocs.zip`.
الملفات في جذر الملف المضغوط لتُستخرج مباشرة داخل `htdocs`.

---

## 1. متطلبات جهاز البناء (وليس الخادم)

- PHP 8.3 أو أحدث مع Composer 2.
- Node.js 20+ وnpm (لبناء أصول الواجهة).
- أداتا `tar` و`zip`.

تحقق:

```bash
php -v && composer --version && node --version && npm --version
```

## 2. بناء الحزمة

من جذر المستودع:

```bash
bash docs/deployment/infinityfree/tools/build-package.sh
```

يُنتج `build/infinityfree-htdocs.zip` ويقوم تلقائياً بـ:

- بناء `vendor` الإنتاجية (`composer install --no-dev`).
- بناء أصول Vite.
- ترتيب جذر الويب: `index.php` و`build/` في الجذر، والتطبيق في `asmaa/`.
- إضافة ملفات `.htaccess` للحماية.
- استثناء `.env` و`node_modules` و`tests` و`cloudflare` و`docs` والسجلات والبيانات المحلية.

لإعادة البناء بعد أي تعديل على الكود، أعد تشغيل الأمر.

## 3. إنشاء الحساب وقاعدة البيانات

1. أنشئ حساب استضافة مجاني واحصل على نطاق فرعي (مثال `xxxx.42web.io`).
2. من لوحة التحكم افتح **MySQL Databases** وأنشئ قاعدة، مثال:
   - اسم القاعدة: `if0_XXXXXXX_asmaa`
   - المستخدم: `if0_XXXXXXX`
   - كلمة مرور قوية (احفظها).
3. سجّل بيانات الاتصال: `DB_HOST` (مثل `sqlXXX.infinityfree.com`), `DB_NAME`, `DB_USER`, `DB_PASSWORD`.

## 4. استيراد المخطط والبيانات الأساسية

افتح **phpMyAdmin** للقاعدة، ثم:

1. اختر القاعدة، ثم تبويب **Import**.
2. استورد `sql/01-schema.sql` (المخطط كاملاً).
3. استورد `sql/02-seed.sql` (الأدوار والصلاحيات وأنواع الملابس وفئات المصروفات — **بلا مستخدمين**).

> لا تستورد ملفات `.env` أو أي بيانات محلية. لا يوجد مستخدم أو كلمة مرور افتراضية.

> إن كان استيراد سابق قد فشل جزئياً (مثلاً خطأ `#1071` بسبب محرك MyISAM)، احذف كل الجداول أولاً (phpMyAdmin → اختر الكل → Drop) ثم أعد الاستيراد. المخطط الحالي يفرض `ENGINE=InnoDB ROW_FORMAT=DYNAMIC` صريحاً فلا يتكرر الخطأ.

## 5. إنشاء حساب المدير الأول (بلا SSH)

على جهازك المحلي (لا ترفع هذا الأمر للخادم):

```bash
php docs/deployment/infinityfree/tools/generate-manager-sql.php \
  "اسم المدير" manager manager@example.com "كلمة-مرور-قوية-١٢-حرفاً"
```

سيطبع جمل SQL. نفّذها في تبويب **SQL** داخل phpMyAdmin. يربط السكربت الحساب بدور
`manager` ويسجل العملية في سجل التدقيق. غيّر كلمة المرور بعد أول دخول.

## 6. رفع الحزمة

1. عبر FTP (FileZilla مثلاً) اتصل بالحساب (بيانات FTP من اللوحة).
2. **قبل الرفع** احذف الملفات الافتراضية في `htdocs` (مثل `default` أو `index.html`).
3. ارفع `infinityfree-htdocs.zip` إلى مجلد `htdocs` (تجاوز حد مدير الملفات 10MB).
4. من **Online File Manager** اختر الملف وفك الضغط **داخل `htdocs`**. يجب أن تظهر
   `htdocs/index.php`، `htdocs/asmaa/`، `htdocs/build/`.

بديل: ارفع محتويات `build/infinityfree/stage/htdocs/` عبر FTP دون ضغط.

## 7. إعداد `.env`

أنشئ الملف `htdocs/asmaa/.env` (عبر مدير الملفات) بناءً على
`env.production.example`، واملأ:

- `APP_URL=https://<نطاقك>` (مع https).
- بيانات `DB_*` من الخطوة 3.
- `APP_KEY`: أنشئه محلياً:

```bash
php -r 'echo "base64:".base64_encode(random_bytes(32)), PHP_EOL;'
```

- `APP_BACKUP_KEY`: مفتاح مشابه احفظه خارج الاستضافة (للنسخ المشفر، اختياري).

> `.env` يُوضع فقط داخل `htdocs/asmaa/`، ويجب ألا يكون قابلاً للوصول من المتصفح
> (يحميه `asmaa/.htaccess`). تحقق من ذلك في الخطوة 9.

## 8. HTTPS

فعّل شهادة SSL المجانية من لوحة التحكم، ثم تأكد أن `APP_URL` يستخدم `https`
و`SESSION_SECURE_COOKIE=true`. التطبيق يفرض مخطط https في وضع الإنتاج.

## 9. التحقق بعد النشر

نفّذ القائمة في `DEPLOYMENT-CHECKLIST.md`. أهم الفحوص:

- فتح `https://<نطاقك>/login` يعمل وتظهر الأصول (CSS/الخطوط).
- محاولة فتح `https://<نطاقك>/asmaa/.env` يجب أن تُرجع **403/404** وليس محتوى الملف.
- محاولة فتح `https://<نطاقك>/asmaa/storage/logs/laravel.log` يجب أن تُرجع **403/404**.
- الصفحات المحمية تعيد التوجيه إلى الدخول عند عدم تسجيل الدخول.
- تصدير تقرير PDF من صفحة التقارير.

## 10. النسخ الاحتياطي والاستعادة (يدوي)

لا يوجد Cron على الخطة المجانية، لذلك **لا نسخ تلقائي**:

- **قاعدة البيانات:** من phpMyAdmin → Export → SQL.
- **الملفات الخاصة والمرفقات:** نزّل `htdocs/asmaa/storage/app/private/` و
  `htdocs/asmaa/storage/app/backups/` عبر FTP/مدير الملفات.
- **خزّن النسخ خارج الاستضافة** (جهازك أو تخزين سحابي خاص). لا تضعها في `htdocs`.
- **الاستعادة:** استورد ملف SQL في قاعدة اختبار أولاً، ثم استبدل الملفات الخاصة.
  اختبر الاستعادة على بيئة منفصلة قبل الاعتماد عليها.

أمر `php artisan workshop:backup` غير قابل للتشغيل على الخطة المجانية (لا CLI)،
ولا يمكن تشغيل `schedule:run` (لا Cron). لذلك لا يمكن إعلان تحقق RPO/RTO.

## 11. قيود يجب معرفتها

- لا SSH، لا Composer، لا Artisan، لا Cron على الخطة المجانية.
- جذر الويب ثابت `htdocs`؛ الحماية بالكامل تعتمد على `.htaccess` (راجع `COMPATIBILITY.md`).
- حد 30,000 inode وحد ملف 10MB عبر مدير الملفات (استخدم FTP للملفات الكبيرة).
- حد 50,000 hit يومياً وحدود CPU قد توقف الحساب مؤقتاً.
- تأكد من امتدادات PHP (`zip`، `fileinfo`، `pdo_mysql`، `zlib`) — يلزم حساب فعلي للتحقق.
- **التجربة ببيانات اصطناعية فقط.**
