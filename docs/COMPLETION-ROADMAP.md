# خارطة إكمال المشروع قبل تسليمه للرفع والاستضافة

هذه خارطة عمل مستمرة مبنية على `SRS.md` ومصفوفة المتطلبات. لا تشمل نشر الموقع أو إنشاء حسابات خارجية أو إدخال بيانات حقيقية؛ يسلم المشروع بعد تجهيز التطبيق والتوثيق محلياً لتكون خطوات المالك الخارجية رفع GitHub، تعبئة أسرار/إعدادات المضيف، ثم اختبار الموقع عليه.

|---|---|---|---|

| 2. إكمال الوظائف الأساسية | إغلاق المتطلبات الوظيفية الناقصة، خاصة تعديل الطلب، المصالحة التاريخية، والتقارير | كل مسار أساسي يعمل من الواجهة حتى قاعدة البيانات مع خادم وصلاحية واختبار | قيد التنفيذ |
| 3. سلامة البيانات والأمان | اختبار قواعد المال والمخزون والتسليم والمرفقات والصلاحيات والتدقيق، إصلاح أي تجاوز | اختبارات تلقائية للحالات الحرجة، وعدم وجود وصول غير مصرح أو أثر مالي صامت | قيد التنفيذ |

| 8. حزمة التسليم | README وتشغيل Fedora، `.env.example` بلا أسرار، دليل نشر/قاعدة/نسخ، إصلاحات نهائية ومراجعة أمنية | اختبارات وبناء نهائيان ناجحان، ملفات GitHub نظيفة، قائمة إعدادات للمضيف وخطوات اختبار بعد الرفع | قيد التنفيذ |

## القيود التي لا يمكن إغلاقها محلياً

- لا نرفع إلى GitHub ولا ننشئ/نضبط حساب استضافة نيابة عن المالك في هذه المرحلة.
- لا يمكن إكمال تجربة المضيف الفعلية أو اختبار cron/الموقع من السودان قبل تحديد المضيف وإعداد حسابه.
- أهداف 50 مستخدماً و95%/ثانيتين على الإنتاج تتطلب بيئة مشابهة للمضيف؛ القياس المحلي مرجعي فقط.
- لا تضاف بيانات حقيقية للتجربة. نستخدم قيماً اصطناعية.
