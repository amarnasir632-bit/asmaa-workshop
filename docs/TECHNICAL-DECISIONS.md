# القرارات التقنية

**الحالة:** سجل الدفعة الثانية. اعتمد المالك SRS v1.0؛ التقنية والاستضافة ما زالتا خاضعتين لتجربة نشر.

## المبادئ

- `SRS.md` المرجع الوظيفي؛ لا يغير هذا السجل سياسة تشغيلية محسومة.
- لا برمجة ولا إنشاء قاعدة/ترحيلات قبل اعتماد المتطلبات والتصميم.
- فصل منطق المجال عن الواجهة، صلاحيات وتحقق في الخادم، قاعدة علائقية، وسجلات مالية/مخزنية بلا محو صامت.
- قابلية النقل والأمان مقدمتان على وعد «مجاني» لا يحقق التشغيل والاستعادة.

## تقييم الخيارات

**PHP + Laravel + Blade + Tailwind:** Laravel إطار منظم وناضج، مناسب للتعلم والصيانة، وBlade واجهة خادمية واضحة. وثائق Laravel 13 تتطلب PHP 8.3+ وامتدادات محددة، وجذر ويب يشير إلى `public` وكتابة `storage` و`bootstrap/cache`. وجود PHP لا يكفي. يمكن بناء الاعتماديات محلياً ورفعها، لكن ذلك يحتاج اختباراً. InfinityFree يعلن PHP 8.4 وMySQL 8، لكنه لا يوفر SSH/Composer/CLI أو مهام دورية مجانية وفق صفحات الدعم، وجذر الويب ثابت على `htdocs`. دليل الدعم يصف قواعد rewrite كحل يتطلب تحققاً أمنياً مستقلاً. إذن Laravel ممكن نظرياً على بعض الاستضافات، لكنه غير مثبت على حساب أو مزود لهذه المهمة.

**CodeIgniter 4 كبديل:** إطار MVC أخف، وثائقه الرسمية تشرح النشر المشترك وفصل مجلد `public` عن ملفات التطبيق، وتوفر تثبيتاً يدوياً دون Composer. يتطلب حالياً PHP 8.2+ و`intl` و`mbstring` على الأقل. يخفف تعقيد النشر دون CLI نسبياً لكنه لا يعالج غياب Cron/النسخ، ولا يوفر Blade/Laravel conventions؛ لم يختبر على حساب فعلي.

| TD-001 | اعتماد PHP 8.3+ وLaravel 13 + Blade + Tailwind كخط أساس قابل للنقل، مع MySQL كمرشح إنتاجي وSQLite للاختبار فقط. | المالك أجاز البدء؛ توافق استضافة فعلية ما زال مفتوحاً. |
| TD-002 | تنفيذ التطبيق الحالي على Laravel 13؛ لا اعتماد مزود استضافة قبل اختبار نشر آمن بجذر `public`. | الاعتماديات موجودة محلياً؛ النشر الفعلي غير مثبت. |
| TD-003 | CodeIgniter 4 بديل إذا كان shared hosting بلا SSH/Composer حاسماً وتعذر جذر Laravel الآمن. | وثائق نشر مشترك وتثبيت يدوي؛ يحتاج اختباراً. |
| TD-004 | MySQL للإنتاج مبدئياً مع قابلية النقل؛ SQLite في اختبارات الذاكرة فقط. | لا قاعدة بيانات إنتاجية منشأة. |
| TD-005 | لا اعتماد InfinityFree إنتاجياً؛ مرشح تجربة فقط بعد اختبار جذر الويب وعزل الملفات وHTTPS والرفع والحدود. | لا SSH/Cron، وحماية `htdocs` لم تختبر. |
| TD-006 | المستندات المالية خارج المسار العام وتقدم بعد تحقق صلاحية خادمي. | مطلب خصوصية ملزم. |
| TD-007 | لا ادعاء بنسخ/RPO/RTO قبل آلية مشفرة واختبار استعادة موثق. | شرط SRS. |
| TD-008 | استخدام `logo.png` و`icon.png` اللذين زودهما المالك، والألوان من دليل الهوية، والخط Tajawal المحلي حسب توجيه المالك الأخير. | أصول الهوية متاحة. الواجهة تستخدم ملفات Tajawal المحلية، ولا يعتمد اختيار Cairo الوارد في اللوحة الإرشادية السابقة. |
| TD-009 | اعتماد `tecnickcom/tc-lib-pdf` لتصدير التقارير PDF مباشرة. | وثائقه الرسمية تذكر العربية وRTL، PHP 8.2+ وComposer؛ الإصدار المثبت 8.80.1 ورخصة LGPL-3.0. يستخدم PDF حالياً DejaVu Sans المرفق ومرخصه. اختبار تضمين Tajawal المحلي أظهر محارف مفقودة بصرياً، لذلك لم نعتمده في PDF. لا يعتبر PDF العربي متوافقاً بصرياً مع هوية Tajawal حتى ينجح اختبار مرئي لاحق. لم يختبر بعد على الاستضافة المستهدفة. [دعم RTL](https://tcpdf.org/examples/E003_rtl_languages/)، [المشروع والمتطلبات والرخصة](https://github.com/tecnickcom/tc-lib-pdf). |
| TD-010 | الطلب الجماعي كطلب `custom` مع امتداد `school_contract` واحد، وقائمة مستفيدين ذات أسماء/مراحل snapshot وبنود `order_items` مرتبطة؛ الطفل الموجود اختياري. | حل تصميمي موثق يلائم نموذج العلاقات ويمنع تكرار دفتر الدفعات. حُفظت تفاصيل العقد وقيم البنود؛ اختبارات الإنشاء ناجحة. |
| TD-011 | رصيد افتتاحي لمسودة واحدة معتمد لكل صنف عند أول حركة؛ تصحيح الجرد كطلب مستقل يطبقه المدير بعد التحقق من عدم السالب. | يمنع تكرار إضافة رصيد أولي ويحفظ دفتر الحركات. |
| TD-012 | نسخ قاعدة البيانات والجداول الخاصة في أرشيف AES-256-GCM، مفتاح 32 بايت سري مستقل، قرص Laravel قابل للتبديل واحتفاظ يومي/أسبوعي/شهري. | أداة مشفرة قابلة لتبديل القرص؛ أضيف adapter S3-compatible واختبر البناء بإعداد اصطناعي وقرص fake، والقرص المحلي يظل الافتراضي. لا تدعي النسخ الخارجي/RPO/RTO قبل ضبط مزود فعلي والجدولة واختبار الإنتاج. |
| TD-013 | مخبأ ملفي افتراضي بدلاً من cache قاعدة البيانات. | يسمح بتشغيل locks للجدولة على الاستضافة المشتركة دون جدول cache إضافي؛ يمكن تغيير `CACHE_STORE` عند توفر خدمة أفضل. |
| TD-014 | اعتماد قواعد حالة السداد والتقارير المقترحة في `DECISION-REQUESTS.md` بقرار المالك بتاريخ 2026-10-14. | التحويل البنكي لا يدخل التحصيل حتى يعتمد المدير؛ الاسترداد يحتسب عند دفعه فعلياً؛ الرصيد المعروض لا يقل عن صفر؛ المبيعات والتحصيل والاسترداد تقارير منفصلة بالتواريخ المحددة. |
| TD-015 | فصل اعتماد مبلغ الاسترداد عن أحداث دفعه الفعلية في جدول `refund_transactions`، مع تسجيل كمية المرتجع ووقت استلامه وحالة فحصه. | يدعم دفعات استرداد جزئية متتابعة بلا تغيير الدفعة الأصلية، ويمنع إعادة إدخال القطعة في مخزون البيع إلا بعد تسجيل فحصها «صالحة لإعادة البيع». |
| TD-016 | استعلام الاسم يعرض حالة مجمعة لكل الطلبات المرتبطة بالاسم المطابق؛ لا يظهر «جاهز» أو «مسدد» إلا إذا كانت كل الطلبات المطابقة جاهزة أو مسددة. | SRS لا يطلب اختيار رقم طلب ولا قائمة، وإظهار الحالة المحافظة لجميع المطابقات لا يكشف سجلات منفردة. الاسم المكرر يطلب رقم التواصل. يظل ذلك غير كاف لإثبات الهوية كما يحذر SRS. |
| TD-017 | تخزين حقول الوقت UTC وتحويل مدخلات العرض من/إلى `Africa/Khartoum`. | يمنع انزياح تاريخ الدفعات والتسليم عند إدخال الوقت المحلي، ويجعل تقارير الفترات تعتمد حدود اليوم المحلي. اختبارات المنطقة الزمنية على SQLite ناجحة؛ يلزم تحقق MySQL لاحقاً. |
| TD-018 | تحديث الإشعارات الداخلية المشتقة عند فتح لوحة التحكم، مع سجل لكل مستخدم وعلامة قراءة/حل. | لا يحتاج خدمة مدفوعة أو مهام مجدولة، ويعكس التأخير والجاهزية والأرصدة الحالية. يقتصر على إشعارات داخلية كما ينص FR-106؛ يلزم تقييم الأداء عند نمو البيانات. |

أضيفت اللوحتان المرجعيتان في `docs/brand/`، ثم زود المالك ملفات الشعار والأيقونة والخطوط في جذر المشروع. تُنسخ أصول العرض إلى `public/` مع الحفاظ على الملفات الأصلية. ملفات Tajawal لا تتضمن ملف ترخيص؛ مصدر/ترخيص الخط يحتاج توثيقاً قبل إعادة توزيع الحزمة خارج نطاق الاستخدام المحلي.

حُسمت DEC-007/008 بموافقة المالك أعلاه. DEC-010: يحدد التطبيق ملفات PDF/JPEG/PNG بحد 5 MiB على تخزين خاص كقيد تقني محافظ؛ يمكن مراجعة الحد قبل النشر. DEC-011 و012 يحتاجان تعريف بيئة قياس/اختبار؛ يطبق حد تقني محافظ أولي للاستعلام قبل النشر ويظل قابل الضبط. مصفوفة الأدوار والأرشفة الخاصة بالموظف موثقة في `ACCESS-MATRIX.md`; تحتاج مراجعة المالك قبل إطلاق النظام. قواعد الإلغاء والخصم والتسليم والمخزون والدفعات كما وردت في SRS ثابتة.
