# نقل التطبيق إلى Cloudflare Workers وD1

## الحالة

هذا مسار نقل تدريجي مستقل عن تطبيق Laravel الحالي. Laravel ومخططه واختباراته تظل المرجع حتى تحقق النسخة الجديدة تكافؤ الوظائف واجتياز اختبارات القبول. لا تستورد بيانات تشغيل حقيقية ولا تجعل Worker بديلاً عن النظام الحالي في هذه المرحلة.

الموجود حالياً قاعدة D1 كاملة البنية مستخرجة من migrations Laravel، وبذور أولية للأدوار والصلاحيات والفئات وأنواع الملابس، ومصادقة مدير/موظف مع جلسة محمية وCSRF وتحديد محاولات الدخول. نُقلت واجهات API للأسر والأطفال والمقاسات وإدارة الموظفين والكتالوج والطلبات والدفعات والتحويلات والتسليم والمخزون والجرد والإنتاج والترزي والمصروفات والإلغاء والاسترداد والتقارير وسجل التدقيق والترحيل التاريخي، وربطت بها شاشات عربية أولية. اختبارات وحدة Worker واختبارات دخـول المصادقة والبناء الجاف ناجحة، وأجريت تدفقات D1 محلية ببيانات اصطناعية. هذا لا يحقق تكافؤاً وظيفياً ولا يعني الجاهزية للنشر العام.

**لا تستخدم هذه النسخة لبيانات تشغيل حقيقية.** ما زالت واجهات الويب ناقصة في إدارة العقود متعددة المستفيدين والتصحيحات المالية والمراجعة التاريخية المتقدمة، ولا توجد ملفات PDF أو استعلام عام عن الطلبات. رفع أدلة الدفع الخاصة إلى R2 وخطة النسخ والاستعادة واستيراد البيانات مع المصالحة واختبارات شاملة مستقلة لم تكتمل. لم تنشأ قاعدة D1 إنتاجية ولم ينشر Worker.

## المعمارية المستهدفة

- **Workers:** واجهات HTTP وعمليات التطبيق؛ JavaScript/TypeScript، وليس Laravel/PHP.
- **D1:** قاعدة SQLite مدارة. ليست بديلاً شفافاً لـMySQL، لذلك يجب نقل كل الاستعلامات والمعاملات والقيود واختبار السلوك المالي والمخزني على D1.
- **R2:** تخزين خاص للمرفقات والإيصالات والنسخ؛ لا تستخدم روابط عامة للملفات الحساسة.
- **واجهة عربية RTL:** تحتاج إعادة بناء واجهات Blade وتحققها بصرياً واختبار صلاحيات كل endpoint.
- **المصادقة والأسرار:** يلزم تنفيذ جلسات آمنة وCSRF وتحديد المحاولات وتهيئة أول مدير دون حساب أو كلمة مرور افتراضية، قبل إتاحة أي صفحة تشغيل.

## العمل المحلي

من جذر المستودع:

```bash
npm --prefix cloudflare install
npm --prefix cloudflare test
npm --prefix cloudflare run db:migrate:local
npm --prefix cloudflare run dev
```

يفحص `GET /api/health` وصول Worker إلى D1. تتوفر أيضاً `/api/setup` للتهيئة الأولية السرية، و`/api/login` و`/api/me` و`/api/logout`. تشمل المسارات المنقولة `/api/guardians`, `/api/children`, `/api/users`, `/api/catalog`, `/api/orders`, `/api/payments` والتسليمات المرتبطة بالطلبات. الوحدات غير المنقولة ترجع 404 عمداً.

لتهيئة أول مدير محلياً، عيّن متغيراً سرياً باسم `BOOTSTRAP_TOKEN` عبر Wrangler (32 حرفاً عشوائياً على الأقل)، ثم أرسل `POST /api/setup` مع ترويسة `x-bootstrap-token` وحقول `name`, `username`, `email` الاختياري و`password` (12 بايتاً على الأقل). إنشاء المدير ذرّي ومسموح مرة واحدة فقط. لا تستخدم بيانات الدخول المحلية في الإنتاج.

## إعداد حساب Cloudflare لاحقاً

بعد اكتمال ميزات النظام واختبارها، أنشئ D1 من مجلد `cloudflare`:

```bash
npx wrangler login
npx wrangler d1 create asmaa-workshop
```

بعد إنشاء قاعدة D1، اربطها في `wrangler.jsonc` باستخدام `database_id` الذي يعيده الأمر، وضبط الأسرار المطلوبة، ثم طبّق ترحيلات الإنتاج وانشر Worker:

```bash
npx wrangler d1 migrations apply asmaa-workshop --remote
npx wrangler deploy
```

لا تنشئ قاعدة إنتاج أو ترفع سجلات قبل اكتمال الوظائف واعتماد خطة النسخ والاستعادة وتحقق العزل والوصول الإداري. بيانات الاعتماد لا توضع في Git أو في ملفات الإعداد.

## شروط اعتبار النقل مكتملاً

- تغطية كل مسارات Laravel الحالية، بما فيها العملاء والمقاسات والطلبات والعقود والإنتاج والتسليم والمخزون والمدفوعات والاستردادات والمصروفات والتقارير والتدقيق والاستيراد التاريخي.
- إعادة تنفيذ صلاحيات المدير والموظف ونطاق السجلات، واختبار محاولات الوصول المباشر غير المصرح.
- إثبات ذريّة معاملات المال والمخزون والتسليم على D1، وثبات أرصدة الطلبات وسجل الحركات والتدقيق.
- نقل المرفقات إلى R2 خاص والتحقق من النوع والحجم والصلاحية والتنزيل.
- اختبار ترحيل اصطناعي قابل للتكرار مع مصالحة أعداد ومجاميع السجلات؛ ثم اختبار نسخة احتياطية واستعادة على بيئة منفصلة.
- نجاح اختبارات الوظائف والأمن على بيئة قريبة من الإنتاج، وفحص RTL على الهاتف والحاسوب، وتجربة تشغيل فعلية قبل تحويل المستخدمين.
