# خطة الاختبارات

الحالة الحالية: اختبارات المصادقة والصلاحيات والعملاء والمقاسات الحالية والكتالوج والطلبات والعقود المدرسية والإنتاج والمخزون والدفعات والتحويلات والتسليم والإلغاء والاسترداد والاستعلام العام والمصروفات وسجل التدقيق وإدارة المستخدمين والنسخ والاستعادة على SQLite مؤقتة. الاختبارات اليدوية والنشر والأداء وبعض التقارير ما زالت مخططة؛ المرجع التفصيلي لكل معرف هو `REQUIREMENTS-MATRIX.md`.

## أوامر التطوير

```bash
php artisan test
./vendor/bin/pint --test
npm run build
```

يجب تشغيل migrations في الاختبارات على SQLite مخصص داخل الذاكرة، لا على قاعدة تشغيل. لا تستخدم بيانات أشخاص حقيقية؛ كل بيانات الاختبارات مصطنعة. لا يُعد تشغيل البناء أو نجاح الواجهة دليلاً على اكتمال الوحدة.

## الاختبارات الآلية المنفذة

- صفحة دخول عربية وتحويل الضيف إلى صفحة الدخول.
- تسجيل الدخول باسم المستخدم، فتح لوحة معتمدة على استعلامات DB، والخروج وإبطال الجلسة.
- رفض الحساب المعطل.
- مصفوفة أذونات المدير/الموظف للعمليات الحساسة.
- إنشاء أول مدير تفاعلياً دون كلمة مرور افتراضية، وتسجيل حدث التأسيس في سجل التدقيق.
- إنشاء ولي أمر وطفل ومقاسات حالية؛ السماح بتكرار الأسماء وتسجيل التدقيق.
- الموظف يعرض الكتالوج ولا يديره؛ المدير ينشئ مدرسة ومرحلة وتركيبة، مع رفض مرحلة من مدرسة أخرى ورفض التركيبة المكررة.
- إنشاء طلب متعدد البنود وتدقيق الحسابات الجزئية؛ تثبيت أسعار الطلب وقياسات الطفل بعد تعديل القياس الحالي.
- منع طفل يتبع ولي أمر آخر، ومنع خصم يتجاوز قيمة البند.
- إنشاء مهمة إنتاج، وإرسال واستلام جزئي، ورفض استلام يتجاوز الكمية المرسلة، وتحديث الحالة التشغيلية حتى الاستلام الكامل، وتنبيه التأخير المشتق.
- الرصيد الافتتاحي لا يطبق قبل الاعتماد، وكل اعتماد ينشئ حركة؛ رفض تعديل يجعل الرصيد سالباً، وربط التصحيح المعتمد بحركة تدقيق.
- العقد المدرسي متعدد المستفيدين والبنود، يرفض طفلاً أو مرحلة من مدرسة أخرى، ويحفظ المبلغ والمقاسات التاريخية.
- الموظف يسجل مصروفاً ولا يرى مصروفات زملائه؛ وسجل التدقيق للمدير قراءة فقط.
- مدير يدير حسابات الموظفين، الموظف لا يغير صلاحياته، ولا يوقف المدير آخر حساب مدير نشط.
- النسخ مشفر ولا يكشف fixture خاصاً؛ retention يخفض العدد؛ استعادة بيانات وملف إلى SQLite معزول تنجح.
- الترحيل المرحلي: الموظف مرفوض، المدير ينشئ دفعة وسجل مصدر، التطابق الحرفي يسجل مسألة بدل تكرار السجل، المراجعة والتصحيح تحفظ النسخة السابقة وسبب التغيير والتدقيق، والأرصدة التاريخية لا تنشئ دفعات أو حركات تشغيلية.

آخر تشغيل كامل: 52 اختباراً ناجحاً و364 assertion بتاريخ 14 أكتوبر 2026. بيئة الاختبار: PHP 8.5 وSQLite memory؛ نجح `vendor/bin/pint --test` بعد تنسيق الملفات، و`npm run build`، وفحص Composer. أضيف GitHub Actions لتشغيل اختبارات SQLite والبناء وPint وComposer validate، ومجموعة الاختبارات نفسها على MySQL 8.4 عند رفع التغيير. لا يمكن تشغيل خدمة CI محلياً في هذه المساحة، لذلك يلزم فحص نجاح workflow بعد رفع المشروع إلى GitHub. الاختبارات لا تثبت توافق استضافة إنتاج. تتضمن المجموعة 3 اختبارات و20 assertion للترحيل المرحلي، واختباراً لبناء S3 adapter بإعداد اصطناعي واختبارات تخزين/تشفير على قرص S3 مزيف. PDF اختبر آلياً كاستجابة PDF؛ الاختبار اليدوي أظهر مشكلة بصرية في Tajawal، وPDF يستخدم DejaVu مؤقتاً.

## خطة اختبارات القبول التالية

| المجال | السيناريوهات المطلوبة |
|---|---|
| الطلب والمقاسات والأسعار | الثلاثة أنواع، بنود متعددة، ثبات snapshot المقاس والسعر، العقود المدرسية والمستفيدون |
| الأموال | دفعات جزئية ومتعددة؛ تحويل pending/verified؛ منع الموظف؛ أدلة متعددة لا تنشئ دفعاً؛ كشف الأرصدة |
| التسليم | رصيد مستحق يمنع التسليم؛ عقد مدرسة لا يسلم قبل سداد إجماليه؛ تسليمات جزئية لا تتجاوز الباقي |
| المخزون | لا مخزون سالب تحت طلب متزامن؛ حركات ذات مصدر؛ فصل عهدة الترزي؛ الأرصدة الافتتاحية والتصحيح بالاعتماد |
| الإنتاج | إرسال واستلام جزئي، رفض استلام فوق المرسل، حساب المتبقي والتأخير المشتق |
| الإلغاء والاسترداد | مدير فقط، خصم يحدده المدير وقت القرار، سجل سبب/مرحلة/هوية/وقت، دفعة أصلية غير ممسوحة، تحقق الملابس المرتجعة |
| الأمان | CSRF، XSS، SQL injection، تنزيل الملف الخاص، فحص MIME/الحجم، طلب HTTP مباشر بصلاحية موظف |
| الاستعلام العام | إظهار الحالتين المسموحتين فقط، تكرار الأسماء، عدم كشف وجود سجل برسائل الخطأ، تحديد المعدل |
| التقارير | مطابقة المبيعات والتحصيلات والمصروفات والديون والاستردادات ومعادلة الربح التقديري؛ اختبار تنزيل PDF تلقائي، واختبار بصري يدوي للتقرير الكامل على A4 ما زال مطلوباً |
| الترحيل | كشف مرشحي التكرار، تواريخ المصادر، السجلات غير المؤكدة، اعتماد تصحيح المدير، مطابقة العدد |
| القاعدة والنشر | migrations نظيفة على MySQL المرشح وSQLite الاختبار، اختبار ترقية/استعادة، إخفاء ملفات التطبيق والمرفقات |
| النسخ | نسخة مشفرة خارجية وفق الاحتفاظ واختبار استعادة شهري وقياس فعلي لـRPO/RTO |
| الأداء | 50 مستخدماً متزامناً، قياس نسبة 95% خلال ثانيتين في بيانات/بيئة موثقة |

## اختبارات يدوية

- مراجعة RTL وملاءمة الجوال/سطح المكتبي والطباعة الفعلية A4.
- اختبار خطوات استضافة فعلية من السودان، حصة الرفع والاتصالات والقيود المجانية.
- اختبار استعادة شهرية لا يمكن استبداله باختبار وحدة.

يُسجل لكل اختبار معرف المتطلب، إعداد البيئة، الإصدار، النتيجة، الدليل والعيب إن وجد. لم تُشغل اختبارات أداء أو نشر حقيقية بعد؛ تمت تجربة الاستعادة محلياً على SQLite معزول فقط.
